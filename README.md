# Battle Ostriches (online, 2 to 5 players on phones)
Node + WebSocket server (`server.js`) holds the authoritative game (`game.js`, all tuning in `CONFIG`) and serves `public/`.
- Run: `npm install && npm start` → http://localhost:3000. Create a game, share the `/?room=CODE` link.
- Tests: `npm install`, then `npm run setup:e2e` once (downloads about 90 MB of WebKit into `node_modules/.pw-browsers`), then `npm test`. It runs every unit suite (`test*.js`, `ai-test.js`, no browser) and every phone suite (`e2e-*.js`, headless WebKit at phone size), one at a time, and prints one PASS or FAIL line each. Logs and pictures go to `shots/` (git-ignored). `npm run test:unit` runs only the unit suites; `node tests/run-all.js lobby` runs only suites whose names contain "lobby". `e2e-live.js` plays the live site and is not part of `npm test`. On Linux the phone browser also needs system libraries: run `sudo node node_modules/playwright-core/cli.js install-deps webkit` once (Ubuntu 22.04 or 24.04). **On GitHub:** `.github/workflows/pr.yml` runs every suite on every pull request and every push to main (in four parts at the same time, so it takes about 15 to 30 minutes; `node tests/run-all.js --shard=1/3` and `--long` run one part). A change counts as passing only when that check (named "check") is green. The job summary lists any failed suites, and the end of each failed suite's log is printed in the run, and the full logs and screenshots are in the `test-output` downloads on the run page. A suite listed in `KNOWN_FAILURES` in `tests/run-all.js` fails for a real game reason that is written down; it prints KNOWN and does not turn the check red. That list is empty as of 2026-11-14: the four suites that were on it turned out to be test mistakes, not game bugs, and are fixed. A suite that fails is run up to two more times: passing on a retry prints FLAKY (and is listed in the job summary); failing all three times is red.
- **While GitHub's checks are off (Brian, 2026-11-15):** "Until GitHub's checks run again, run the full test suite before every merge and paste the pass count in the pull request." GitHub stopped running checks on 2026-11-15 because the monthly free minutes ran out or billing needs attention. Until the check runs again, a pull request may be merged only after the full suite (`node tests/run-all.js test ai-test`) passes on your machine and the result (for example "36 of 36 suites passed") is pasted in a pull request comment, along with Brian's yes.
- Tools that make screenshots or theme files are in `tools/`. Run them from the repo root, e.g. `node tools/make-home-shots.js`.
- Deploy: Render (render.yaml, free plan: New → Blueprint, pick the repo) or Fly.io (`fly launch --copy-config && fly deploy`, uses Dockerfile).
Games live in memory: a restart or free-tier sleep ends games in progress.

## Balance (sim.js)
`node sim.js 6000` pits an ostrich bot (coldest-egg routing, guards when the vulture is near, carries spotted eggs away, obeys the sit cap) against a vulture bot (hunts footprints, uses smell history to rule squares in/out, throws at guarded/spotted squares).
CONFIG in `game.js`: rounds 30, warmth 15, no sit limit, ostrich walk 2 (carryWalk 1), kickPush 3 (badger 2, wraps at the edge), fly 2, throw adjacent, 1 stone (refill at a rock pile), smell 1, food every 15 turns, `hunterGoal` per one-hunter mode ('all' in 3 players, 'first' in 5). `node ai-test.js` on 2026-11-06 (older rules): vulture bot wins about 48% on Normal and 43% on Easy. Stone throws animate via public/smash.js.

## Rules that are the same in every game type (rulebook v2, 2026-11-07)
The source of truth is `docs/reviews/RULEBOOK-v2-2026-11-07.md`. A map of the other docs is `docs/README.md`. Numbers live in `CONFIG` (game.js), `T3` (three.js), `TH` (hunt.js) and `TM` (team.js) and reach the role cards through `Roles.rulesFromModules()`. Tests: `node testv2.js` covers each section in all four engines.
- **Everyone moves 2** (hyena, badger, vulture; ostrich 2, carrying 1). Anyone passes over anything; only the landing square counts. Nobody lands on a wrecked square; a bird does not land on an animal it can see (so only on a buried badger, which catches it). Hunters may land on birds and on the other hunter.
- **Stones (`B.resolveThrow`):** every stone wrecks an ordinary square (marks `stone`, or `hit` when an egg broke there); leaves and rock piles never. A stone pushes any animal on its square 2 away from the vulture and brings a buried badger up. A stone thrown at an ostrich is kicked back onto the vulture's own square; the vulture is set down on the nearest open square (ties: farthest from the ostrich). On a leaf or rock pile it bounces and goes one square past; a kicked-back stone is never kicked back again. Never at the teammate's square.
- **Ostrich:** a carried egg is not warmed; eggs go cold after `warmth` (15) rounds; eats every `food` (15) turns; no sit limit, and a sitting ostrich is shown to every bird (`sittingAt` in the views, never to hunters); never puts an egg on or next to a leaf. **Kick:** pushes 3 (badger 2), wraps around the edge, stops before a wrecked square or an animal that is up. **Carry is visible to every bird** (Brian, 2026-11-16): a vulture sees an egg in an ostrich's beak in every mode, including 2 vs 2 and 5 players, using the same carry drawing as 2-player, 3-player and Hunters. A hunter still sees no birds. A number is shown only when the game has more than one bird of that kind. Where it shows, it is a small rounded square at the bottom left of the square, the same in every theme (Brian, 2026-11-17). In Black and white the square is white with a black number, so it stays readable on a black bird and inside the YOU frame. A lone bird, including 2-player birds and a single hunter, has no number.
- **Catches:** 2026-11-16: After a catch, the bird lands on a random open square exactly 3 squares away (was exactly 2). The distance is king-move (Chebyshev), the same one walking and the 2-square sense use (`B.relocateCaught`). The landing does not wrap around the board; the old 2-square scramble did not wrap either. Open means in bounds, not wrecked, and not occupied by an animal that is up, the same squares the old landing allowed (a buried badger's square is still allowed). If no square exactly 3 away is open, the bird lands at the nearest greater distance that has an open square, and only if every greater distance is empty, at the nearest smaller distance. If no square at any distance is open, whoever moved this turn goes back to where they started. No missed turn. An egg in the beak drops on the catch square. Hunters are never told the landing square. A badger that bursts out with no recorded direction still uses the 8-direction scramble (`B.scrambleTo` at 2), not this landing. **Hunters meeting:** the mover pushes the other 2; a hyena that walks onto a buried badger shares the square.
- **Hyena Pounce (two steps):** it walks 2; if it smelled a bird and did not catch, it smells again and may take one more step. The squares where both readings agree are marked as the most likely area (`.maybird.bright`).
- **Shot clock:** if an ostrich's time runs out while it stands on an egg (not carrying one), that egg is still warmed (Brian, 2026-11-15). How to play holds that clock the same way the role card does, and lets it run again when the page closes (2026-11-16).
- **One tap, one turn:** every act is stamped with the round, whose turn it is, the hunter's bonus turn, the sense count, and a turn number from the server. The server drops an act whose stamp is not the current turn, in 2-player, 3-player, team, and Hunters games. A double tap on Stay or Burrow cannot spend the bonus turn after a knock-out, and a step tapped in round 1 cannot move the ostrich in round 2. After the phone sends an action it ignores further action taps (board, Stay, Burrow, the ring, Kick) until the next update. A tap queued during the short sniff pause is still cancelled if the board changed while it waited (`e2e-queued-tap.js`). Tests: `testturnstamp.js`, `e2e-turnstamp.js`.
- **Badger out of time:** if the badger's time runs out before it is buried, it just loses its turn. It does not dig in, and nobody is told "The badger dug in!" A badger that is already buried stays buried (Brian, 2026-11-15; test: `testbadgertimeout.js`).
- **Who hears "The badger dug in!":** only the badger, and a bird that saw the dig. A bird that did not see it gets no line and no dig event. The mound still goes only to a bird that saw it, and only while the badger stays buried. The hyena is not told. Same in 3-player, Hunters, and 4- and 5-player games (Brian, 2026-11-16; test: `testv2.js`).
- **End line when the vulture is out and the eggs went cold:** the ostrich is still on the board, so the end screen says "The vulture is out and the eggs went cold, so the hyena wins." ("badger" when the badger hunts), not "Both birds are out." In Hunters it starts the same way, then names the winning hunter or the tie (Brian, 2026-11-15; test: `testendreason.js`).
- **3-player hunter goal:** the hunter wins when both birds are out, not at a number of catches. The old goal, 4 catches, could only happen once both birds were knocked out anyway, so play does not change; the cards now say "You win when both birds are out." (hunter) and "The hunter wins when both birds are out." (birds), and each phone shows its 3-player card once more. The double turn after a knock-out stays (Brian, 2026-11-15, rule clash R5; test: `testr5goal.js`). The boxed-in ostrich (R6) is left as is.
- **Endings:** in round 30 the hunter (both hunters in Hunters mode) still takes its last move before time is up, in every mode (Brian, 2026-11-15); a knocked-out bird loses and the game goes on; a side is out when all its birds are out or it cannot meet its goal; the last side in wins; time with no goal met is a draw. The views carry `endWhy`, one plain line. `CONFIG.hunterGoal` sets the hunter's goal per mode: 3 players `catches:3` (also `all`, `first`), 2 vs 2 + hunter `first` (also `all`). Hunters mode: more knock-outs, then more catches, then a tie.
- **Big events go to every phone as one line** (a kick, a stone kicked back or landing softly, a badger coming out, the hunters meeting, a catch, a knock-out, the start-of-game line `Roles.huntLine`), through the `#announce` queue. The square appears only for a player who can see it: birds see birds, a bird sees a hunter within 2 (never a buried badger), hunters see no bird.
- **A surprise hit continues on its own** (2026-11-16). Kick, catch (including a hidden badger), knock-out, stone, egg smash, badger burst, and a hunter shove still open with "Look out!" for the player who was hit, then the cartoon, then the slide. There is no "Tap to go on." button. After the slide, that player gets a reading pause of one second, or 0.3 seconds a word when the result line is longer ("The ostrich kicked you 3 squares!" is 1.8 seconds). A 3-square kick is about 6.6 seconds in all, and that player's shot clock waits through the pause. A watcher who can still see the kicked hunter plays the kick slide at once, without waiting for the cartoon. If that hunter is already outside the watcher's sight, the phone skips the slide and does not say "Hyena near!" or "Badger near!". The slide still uses only squares that phone was already allowed to see. Tests: `testsurprise.js`, `testsurprisefix.js`.
- **Catch cartoon on every phone** (2026-11-16). The catch picture, and the knock-out picture, plays for every seat in 3-player, 5-player, and Hunters. The drawing is the two animals. It has no square, so it does not show the hunter, the scramble landing, or a burrow. The board slide still runs only for a seat the server already sent both squares to. Who is sent the catch square is unchanged: the caught bird, the hunter who caught, a bird who can see that hunter, an eliminated bird, and (when the game is over) everyone. A hunter is still not told the landing. A buried badger is still hidden from birds who did not see it. Tests: `testcutaways.js`, `e2e-catch-bubble.js`.
- **Badger sayings** (2026-11-16). Each quote is its own bubble near the badger's square, about one second, or 0.3 seconds a word when the line is longer. It does not wait in the status line. A saying already queued still plays if the turn changes before it is shown. A saying for a turn that is already over is not added. Who sees which saying is unchanged (`public/badgerlines.js`): a hidden burrow, a stay, or ambush sight is only on the badger's phone. The bubble does not cover a piece. Tests: `testbadgerbubble.js`, `e2e-catch-bubble.js`.
- **Teammate throw** (2026-11-16, Brian). In 2 vs 2 and 5-player games, a vulture in Throw mode that taps its teammate's square within throw reach sees "Your teammate is there." A square out of reach is still "Too far." With no stone it is still "No stone. Go to rocks." The teammate's square stays off the throw list. Test: `testthrowtap.js`, `e2e-catch-bubble.js`.

## Gameplay UI
Actions (Carry, Sit, Kick, Throw, Stay, Burrow) are buttons under the board. Walking and flying are taps on the squares you can reach. The hint says why an action is unavailable. There is no separate Vulture's Eye Island screen in this repo. The ostrich does not get a "Vulture smells nothing" popup. The vulture still sees its own sniff.

Hyena sense is still only yes or no inside a 2-square box, diagonals included. The hunter sees where a bird may be. Nothing points at a bird. When a living bird first sees a hunter, the board says "Hyena near!" or "Badger near!" once. A kick that has already carried that hunter out of sight does not play a late slide or repeat that line. A burrowed badger does not trigger it and stays hidden from the birds. The player who is the badger still gets their own graphic on the board before burrow and while burrowed, on every theme.

Before the badger digs in, its Burrow button and hint say "A bird will see you dig in." or "No bird will see you dig in." Its "bird near" check reaches 2 squares, the same as bird sight, so the warning is always right without naming the bird. After the dig, the badger's phone says "A bird saw you dig in." when one did, and "The badger dug in!" when none did. A bird that saw the dig is told "The badger dug in!" and gets the mound. A bird that did not see it gets nothing: no line, no dig event, no mound. The hyena is not told either. The badger's role card and hunter pick say "Tap Burrow to hide. Birds within 2 squares see where." (Brian, 2026-11-15 and 2026-11-16; test: `testv2.js`).

An eliminated bird is off the board. A stone on the egg it was covering smashes that egg. A stone thrown at a living ostrich is kicked back.

A catch that does not knock a bird out shows HURT on that animal. OUT means eliminated. An eliminated human bird then gets a read-only view of every animal and the eggs (`god: true`) and is sent no actions. Until that moment the old visibility rules apply, including a living hunter seeing no birds or eggs. Hunters are not eliminated mid-game, so they do not get that view before the game ends.

The ⏱ control shows the round counter and the shot clock. It is its own clock button in the top bar, just left of the ⋯ menu, in every game with a shot clock (Brian, 2026-11-15: "Timer needs its own button"); it is no longer a line inside the ⋯ menu. New games start with the turn timer off (Brian, 2026-11-16). The Turn timer switch stays in the gear menu, and the host turns it on. A new lobby room is created with `clock: false`, so there is no shot clock until that switch. `room.settings.showTimers` (set from create `showTimers`, default true) is copied onto each view as `showTimers`, and the view is off while the turn timer is off. A phone with nothing saved follows that: localStorage `bo_timers` missing means off, and `1` or `0` still overrides the display. Rounds left is still `rounds - round + 1`, counting the current round. Hiding the clock does not stop it when the turn timer is on: the turn still ends after 10 seconds. Catch counts, movement, hunter visibility for living players, the badger speed boost, and win conditions are unchanged.

## Themes
Black and white is the default. The rest are Classic, Nature, Neon, Field notes, Golden hour, Papercraft, Arcade, Toybox, Tactical, Savanna storm, Volcano, Comic pop and Pharaoh sunset (`public/theme.js`). Pick Theme in the menu, or open `?theme=nature`. The choice is saved in localStorage `bo_theme`.

In a 4- or 5-player game every bird that phone is allowed to see is drawn, including the teammate and the birds on the other side. Black and white and Classic draw the plain piece. Every other theme hides that piece and paints the same drawing in the moving layer, one sprite per bird (`public/fx.js`). The small number stays on the bird, and a teammate keeps the light outline. Test: `node e2e-team-themes.js`.


## Words and signals (UX pass, 2026-11-07)
Pick-your-animal subtitles (`lobby.js`): Ostrich "hide eggs", Vulture "hunt eggs", Hyena "Pounce · 2 catches" (Brian, 2026-11-15), Badger "Burrow · 2 catches".

Source: `UX-WORDS-AND-VISUALS-2026-11-07.md` in the Drive folder. Hints are 3 to 7 words and start with the verb; a wrong tap shakes the square and says "Too far." or "Not there."; role cards are a title and 4 short lines; no text names a color or a look. The marks live in `public/signals.css`, loaded after every theme, so a theme restyles floors and animals and never a signal: a dot to move (`.mvdot`), a lit square to throw (no circle-plus and no crosshair; a found egg is the filled egg, and the squares light once Throw is picked), a ring on an animal you can kick (`.kring`, then dots along the push and a faded copy where it lands, tap again to kick), one X for every wrecked square, one ring under your own animal (`.youring`), one message slot above the board for every hint, toast and tip (red only for bad news to that phone), and a slightly darker fog beyond 2 squares for birds only. `e2e-signals.js` measures the move dot against the tile on all 13 themes (3:1 or better), checks the whole board fits at 390 x 664, and writes screenshots to `shots/ux/`.

Usability fixes, part 1 (source: `COLD-AUDIT-FIXES-2026-11-07.md`, fixes 1 to 5). `public/part1.css` loads last. `public/nextstep.js` marks the next step of each animal's loop on the board and uses only what that player's own view holds (`node teststep.js`): a pulsing Throw button for a vulture with a stone (no crosshair on the found egg), rock piles and bolder moves toward the nearest one without a stone, the lowest egg or the leaf for the ostrich once low, a ring on a bird next to a buried badger, the pulsing bird outlines for a hunter. Every message, tip and pop-up is drawn in the one slot above the board (`#msgslot`), never on it; the YOU tag hangs above the square; your ring wraps the square and refills on arrival; squares you can move to are lit (the whole square filled yellow with a dark edge, `signals.css`; nothing is lit while eggs or the start are being placed); one look per meaning for anything about an animal, drawn as one small shape in the top-left corner of the square and never over its middle (`T3UI.mark`, styled in `part1.css`). "May be here" is the shape dashed and white with no fill: an egg in the 8 squares around where the vulture last landed, a bird in each square of the hunter's sense (during a Pounce only the squares inside both readings, all the same look). "Is here" (known to be there) is the same shape, same size, filled white with a dark edge: a found egg, the ostrich's own eggs (each with its warmth number beside it, or in the bottom-right corner on the square the ostrich stands on), and a burrow a bird saw dug. Animals stay full size, and nothing on the board is yellow except squares you can move to. Only the vulture's latest landing shows the "may be here" outlines, and a throw does not wipe them: they stay until the next landing (`sniffKeep`, drawn by `outlineSniff`). A throw still clears `sniff`, so the spoken result is not repeated and the computer vulture (`ai.js`) does not change its choices. A kick or a catch does not leave a ring on the landing square, in any theme. `.push-cause` is a short outline on the animal that did the kicking, only while the slide plays, and it is not that ring. Tests: `node testplaylook.js` and `e2e-playlook.js`. The only stone asks "Throw anyway?" before it is thrown anywhere but at a found egg, and a wrong tap or a miss pulses the right square. How to play opens at its top with four pictures drawn with the real marks (`.mini`). `e2e-part1.js` checks all of this on a 390 x 664 phone, including that no text sits over the board in a 2-player, 3-player, Hunters and 2 vs 2 game with each kind of message showing.
